# Attached Git worktrees

Experimental Unix-only local capture and refresh. The existing clone is authoritative: attachment operations never write its index, working files or refs. Native candidate publication, forge updates and automatic conflict resolution are not implemented by this interface.

Initialize a separate native data directory first. Attach the exact checkout root with an absolute Git executable (2.45 or newer), an actor, remote, remote-tracking target, output branch name and explicit source selection:

```sh
agentscm --data-dir /path/to/native attached-worktree attach \
  --git /usr/bin/git --repository /path/to/clone --actor alice \
  --remote origin --target main --output agents/alice \
  --source worktree --path src --path tests --operation-id attach-alice
```

`committed` requires `--path .` and reads the whole immutable HEAD commit as canonical Git bytes. `worktree` reads raw selected filesystem bytes, including selected untracked files; its serialized source kind is `worktree_raw`. It does not perform Git text, EOL, ident or encoding conversions. Consequently raw CRLF content can differ from canonical committed LF content. Configured clean/smudge filters are refused. `index` is explicitly unsupported; commit the intended index state or select raw worktree paths instead.

Worktree capture uses the shared workspace exclusion selector, including user Git excludes, local `info/exclude`, per-directory `.gitignore`, `.agentscmignore` and private workspace exclusions. HEAD/index inventory preserves tracked ignored files and staged additions. Git and workspace metadata are reserved. Unselected working paths are not read as source; the complete candidate still contains immutable committed branch content. Exclusions are not secret detection: deliberately selecting an untracked credential file can capture it. Credential-bearing remote identities, including userinfo and `@` forms, query strings and fragments, are refused without echoing their contents. No fetch or network mutation is performed. A missing remote-tracking ref never falls back to a local branch or tag.

SSH `user@host:path` and `ssh://user@host/path` identities, including the common `git@` username forms, remain unsupported in phase 1. Phase 2 needs a credential-free transport identity that does not confuse a username with authenticated ownership. This local interface does not authenticate the `actor` label or establish who owns a Change.

`state --id ID` reports identity and the first bounded mapping page. The library's `mappings(id, after_commit, limit)` provides further pages (maximum 256). Each exact Git commit and tree maps to an immutable native revision; distinct commits may share a native revision. Worktree identity includes the per-worktree Git directory and index, not just the common Git directory.

`capture` and `refresh` require `--expected-generation N` and `--operation-id ID`. Retry the same caller inputs and operation ID after an uncertain response: the original complete outcome is returned even after later advancement. Changing inputs with an old operation ID is an error. A new operation must use the current generation; no-op completion uses the same transaction fence as advancing completion.

The recorded baseline is the imported Git target. The candidate separately retains committed branch-ahead work and selected edits. Refresh first incorporates local source changes using the previous observed local source as its verified base, then incorporates an advanced target using the recorded target baseline. If the exact target is already an ancestor of HEAD, refresh verifies that retained candidate-only content came from the prior recorded target and adopts Git's resolved HEAD plus the selected raw overlay. This permits an ordinary clean merge or explicit conflict resolution without reapplying the target. Ambiguous native-only content still blocks. When the target is not in HEAD, disjoint path changes merge and divergent same-path edits block, including otherwise mergeable text. Refresh never applies the candidate to the checkout. Capture refuses a changed target until refresh imports it. HEAD and target rewrites block both operations. Absent ancestry objects and Git process failures (including timeouts) are reported as unavailable ancestry. A shallow boundary can hide parent relationships and appear as divergence even when the full history would prove ancestry. Restore genuinely rewritten ancestry to continue; supersede and rebase recovery remain unsupported. No merge session or native integration event is fabricated.

All captures and current comparisons are historical observations. Their fingerprints include selected bytes/kinds/absence, Git inventory and observed exclusion inputs. `changed_paths` is relative to the captured HEAD snapshot, not the preceding native candidate, and worktree source remains raw bytes. Completion revalidates those inputs and Git identity under the journal generation fence, but ordinary filesystem editors cannot be locked atomically by this protocol. `validate_current(engine, id, generation)` performs a fresh comparison and returns a subject fingerprint; it is not a freshness lease. A future publisher must perform another exact-current comparison at its publication boundary and preserve uncertainty about subsequent edits.

`bind_context(authority, operation, id, generation, change)` explicitly binds an existing Authority Change and its exact candidate context from the same native data directory and repository identity. The context target must match the Git target name and have no native target/base: this is an unlanded check context, with the Git baseline retained separately in the attachment. Native landing is not required to run exact source-path checks. Binding is lifetime-stable for the attachment: a different Change cannot replace it, including after the Change closes or lands. The local `actor` is an unauthenticated label and is not asserted to own the Change. Every source, exclusion-input or target advance invalidates the attached context pointer. A consumer must recheck the actual Authority current pointer and policy before using evidence. A retained pointer alone does not establish current qualification or publication authority.

The private journal is bounded and held under a lifetime local-recovery lease. It retains at most 256 attachments, 4,096 operation IDs and 4,096 Git mappings per attachment, 10,000 rows total and 256 MiB of retained state/outcome JSON. Each state or complete operation outcome has a 256 KiB JSON ceiling, including changed paths; exceeding it rolls back the operation without partial journal state. Successful no-ops consume operation rows because same-ID replay is durable; operation IDs are never silently pruned. Phase 2 automation must compare external state and reuse an uncertain operation ID rather than issue capture/refresh no-ops as a polling loop. One attachment therefore cannot consume every per-attachment slot, while the separate total bounds still protect the data directory. Exhaustion fails closed. There is no automatic migration or supported recovery into a new journal; preserve the original data and checkout and escalate rather than deleting retained IDs. Unknown, malformed or incompletely initialized foreign journals fail closed, while a validated empty journal does not disable standard backup. Standard backup/restore explicitly refuses a nonempty attached store until attachment recovery has been qualified. Do not copy a live journal as an unmanaged backup. The executable-mode probe must be on the worktree's filesystem; a separate native data mount is currently refused for raw worktree capture.

Detached HEADs, unmerged indexes, skip-worktree or assume-unchanged entries (and therefore sparse-checkout worktrees using those flags), submodules/gitlinks, configured content filters and index capture are unsupported. Shallow or partial clones work only when every required commit, tree and ancestry object is already local; lazy fetching is disabled. Non-UTF-8 selected relative paths remain unsupported, although Unix-native workspace roots and exclusion-file paths may contain raw non-UTF-8 bytes. A blocked same-path refresh remains attached and unchanged: resolve by merging the exact target in Git and committing the resolution, then retry refresh; if the target is not an ancestor of that HEAD, phase 1 has no supersede/abandon operation for the attachment ID.
