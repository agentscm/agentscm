# Slack capability matrix

This is the capability map for the optional Slack adapter. The AgentSCM routes and MCP names below are the authoritative capabilities found in this repository. The implemented surfaces are locally exercised using synthetic Slack/API events; Slack API access, workspace installation, scopes, and rollout status are unverified here. A documented Slack surface is not evidence that this adapter currently has access to it.

Auth reuse: use the existing agent bearer surface for read-only Slack journeys (`Reader` in `src/hub/http.rs`) and a dedicated per-human read-only credential with an optional opaque in-process coordination grant for the explicitly structured start/checkpoint mutations. Keep human administration, execution, approval, native landing, source transfer, and forge administration on the existing browser `HumanSession`/workspace-cookie flow (`src/hub/workspace.rs`, `src/hub/workspace_http.rs`). Agent tokens do not authenticate as human sessions.

## Implemented first slice

The initial adapter surface is a private App Home showing status, work, blockers, coordination, handoffs, and workflow evidence. Slash commands open private views. Structured start and checkpoint actions use short-lived modals and a dedicated per-human read-only credential with an optional opaque in-process coordination grant. The Open Hub fallback leads to the existing browser UI for workspace administration, execution, approval, native landing and source transfer. Shared-channel disclosure, arbitrary remote control, raw message ingestion, and automatic Slack-side mirroring are outside this slice.
