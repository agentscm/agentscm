# Roadmap

> **Alpha: not for production.** APIs, CLI, storage and schemas may change without migration. See the [README](../README.md) for status and the [changelog](../CHANGELOG.md) for known limits.

What AgentSCM does today and what is planned, in terms of what a user can do. Nothing here is a delivery date or a commitment, and nothing has been measured at tens or hundreds of concurrent agents.

Status labels follow the [specification](spec/agentic-scm.md), plus **Experimental** as a stricter qualifier on rows the specification calls Implemented:

- **Implemented**: in this repository's code and tests. The native ledger rows are the trusted-local, single-operator profile; hub rows are a multi-user service that is alpha. Not a production or scale claim.
- **Experimental**: implemented, but exercised only against fakes or a narrow environment; the limits are named in the row. Treat it as less settled than **Implemented**.
- **Partial**: some of the behavior exists; the gap is named.
- **Proposed**: described, with no implementation yet.

| Capability | What a user gets | Status |
|---|---|---|
| Early collision warnings | See which branches and worktrees touch the same files before a merge, from the CLI or `GET /v1/collisions`. Git only, read-only, bounded by a deadline and output budget in the service. It sees only what is in the scanned repository. See [collisions](collisions.md). | Implemented |
| Immutable ledger | An append-only record of exact revisions, review contexts, approvals and protected-target moves, with durable retries. Local SQLite, one operator. Revisions carry regular, executable and symlink entries. | Implemented (experimental; local, one operator) |
| Task-scoped source and workspaces | Explore immutable source without a checkout, materialize explicit paths into an ordinary local workspace, expand the scope deliberately and checkpoint a complete revision without deleting unmaterialized base paths. See [task workspaces](advanced/task-workspaces.md). | Implemented (experimental; trusted-local): explicit source objects must already be present; no virtual filesystem, automatic dependency discovery or authenticated remote task mutation |
| Git shadow workflow | Capture a clean Git commit, work and land natively, reconcile with Git and export to a local mirror you own. Git stays authoritative; nothing is pushed. | Implemented (experimental; local, one operator; one-way snapshot; export v2 preserves executable and symlink entries; legacy export v1 and reconcile refuse them) |
| Attached Git worktree lifecycle | Attach an existing named-branch checkout without writing its files, index or refs; capture committed or explicitly selected raw source; bind and qualify an exact native Change; retain Git/native/candidate mappings; refresh conservatively; and publish a separate leased branch and GitHub PR without native landing. See [attached Git worktrees](advanced/attached-git-worktrees.md). | Experimental (Unix, trusted local): local bare and loopback HTTPS transport with existing Hub/fake GitHub PR recovery; index capture, live forge/SSH qualification, provider protection admission, GitLab MRs, nonempty-journal backup/restore, attachment-level supersede/rebase recovery, common SSH remote forms, submodules and unavailable shallow/partial history are unsupported; this is not native authority cutover |
| Deterministic checks | A built-in source-path check bound to the exact revision and review context. | Implemented (experimental; local, one operator) |
| Isolated command checks | Run a declared command against an exact revision in a locked-down container, bind the result to approval, cancel or recover a run, and turn a successful agent run's output into a candidate revision. See [execution](advanced/execution.md). | Experimental (trusted-local, Unix with Docker): hostile-boundary canaries qualify only the runtime they run on; no unattended recovery after a controller crash; records are unsigned; not a sandbox for arbitrary hostile code |
| Source-bound skill workflows | Run a bounded graph of exact-file checks and pinned command recipes on one immutable revision, retain results and explicitly cancel or recover command work. See [skill workflows](advanced/skill-workflows.md). | Experimental: Unix/Docker for commands; configured native targets can require a finalized graph receipt; legacy Hub/MCP/dashboard are inspection-only |
| Agent-driven workflow automation | Trigger selected workflows from agent events, expose authenticated execution tools and require current workflow results at a controlled landing boundary. | Partial: optional Claude Code and Codex CLI Stop triggers (local and hosted) and read-only agent-owned task Stop modes (`task-stop`, `task-codex-stop`), with a thin instruction entrypoint in the `init-repo` block. Live CLI qualification (2026-10-20, one machine, synthetic fixture) covers local `claude-stop` in Claude Code print mode and local `codex-stop` in `codex exec` with `--dangerously-bypass-hook-trust`; hosted and agent-owned stops and editor/desktop surfaces are fixture-only. The Stop loop allows at most 8 consecutive automatic continuations per agent, session, workspace and change. Also a previewed local installer (`skill-workflow install-stop`); exact-current native target gate, opt-in server execution API, workspace-authenticated HTTP/MCP agent-task facade, and a Unix CLI for enrolled exact-source local collection and signed upload. Task-only profiles do not bootstrap source to another machine; existing file-edit hooks remain contention-only |
| Community workspace | Share members, settings and workflow execution, with explicit approval and native landing controls. See [workspace pilot](advanced/community-workspace.md). | Experimental single-server trusted-team pilot: persistent independent roles and browser sessions, bounded serial queue, repository-scoped tokens and restart-to-Unknown without replay. No source upload/context management, automatic failover or live two-machine qualification |
| Skill distribution and agent adapters | Select pinned packages or author local skills; run review tasks through operator-selected agents or provider credentials. | Partial: bounded Claude Code subscription adapter; no catalog installer or general provider adapter |
| Multi-user coordination hub | `agentscm hub serve` on SQLite or PostgreSQL, with local or S3-compatible object storage: sign-in with GitHub or GitLab (gated by the person's access to a connected repository), owner-scoped expiring agent tokens and an event log. General events are append-only; stand-up work has explicit operator retention. See [hub](hub.md). | Implemented (alpha): legacy login sessions live in memory; workspace browser sessions persist separately. The hub does not terminate TLS and has no TLS to PostgreSQL. Optional profiles join selected native workflows |
| Declared work intent and notices | Agents announce the files they are about to edit; overlapping agents get attributed notices across machines, from the hub API, `agentscm intent`, a Claude Code hook, the hub's MCP endpoint or its per-agent hook endpoints (Claude Code, Codex, Cursor, Copilot). See [intents](intents.md). | Implemented (alpha): advisory, except that the first contested edit per session and file is refused once on Claude Code, Codex and Copilot hooks (a repeat passes); notices are collected by long-poll or on the next call, not pushed; only announced work is visible; the hook endpoints are tested with fixture payloads built from each agent's documentation, not in live agent sessions |
| Asynchronous agent stand-up | Retrieve current unfinished engineering work and a bounded change briefing, atomically claim or join explicit work, report progress/decisions/blockers and leave a resumable handover. Plain Git work and linked GitHub/GitLab issues use the same Hub records. See [stand-up](standup.md). | Implemented (alpha): durable repository-scoped SQLite/PostgreSQL records, CLI/MCP/HTTP participation and read-only Hub inspection; agent checkpoints are self-reports, existing hooks do not infer meaningful progress, stale/unknown remains claimed, and real-client/two-machine/live-forge/PostgreSQL deployment qualification remains incomplete |
| Two-way forge coordination | Observe open pull or merge requests and branches from GitHub and GitLab; optionally post a comment and a status (off by default). | Experimental: GitHub and GitLab, tested only against in-process fakes |
| Publish branch and pull request | Turn a native revision exported to a mirror into a GitHub branch and pull request, through the hub. | Experimental: GitHub only and not yet verified against live GitHub; GitLab merge requests are not implemented |
| One container, two machines | The hub as a container with shared object storage, with an end-to-end test of two agents on two machine names. | Implemented as compose profiles and an end-to-end test on one host; a test on two real machines is still needed |
| Authenticated team profile | PostgreSQL-backed scoped identities and draft publication through the `agentscm team` commands. | Partial: no approval or landing admission |
| Automated model review | A bounded review adapter that records coverage and findings against the exact reviewed bytes. | Experimental Claude Code adapter through the finite controller; explicit budget/dispatch reservations and no candidate tools. Broader adapters and live scale qualification remain planned |
| Optional native authority per target | Exact commit-to-revision and pull-request-to-change mappings in the ledger, a verified round trip back to Git and a recorded decision per target, so a team that chooses to can make the ledger the landing authority for one target while Git and the forge stay fully supported. Optional and reversible; most teams can stay on Git. See the [path to cutover](spec/agentic-scm.md#7-path-to-cutover). | Proposed |
| Measured scale | Published capacity, latency and cost at tens to hundreds of agents. | Proposed: not measured |

Attached candidate preparation inherits the 100,000-object/128 MiB seed ceiling and refuses shallow metadata and grafts. Journals are finite without pruning; closed/merged PR lineages are terminal. These limits and explicit no-effect prepare abandonment are described in [attached Git worktrees](advanced/attached-git-worktrees.md). This path does not implement automatic native cutover or history migration.
